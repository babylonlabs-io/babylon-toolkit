# Firmware pin

The host code in this package, the wallet-connector `ledger-vault` provider and the
ts-sdk's deposit-terms, delegated-claim and `primitives/psbt` modules mirror rules of the
Ledger Babylon Vault app. Every statement about device behaviour in their comments was
checked against this revision.

| | |
| --- | --- |
| App | Babylon Vault 0.11.1 |
| Firmware | `LedgerHQ/app-babylon-vault-dev` (private), `develop` @ `2733b7dd9`, release tags `*_0.11.1_sdk_v27.1.2` |
| Base Bitcoin app | `LedgerHQ/app-bitcoin` @ `72b5630`, the `bitcoin_app_base` gitlink at `2733b7dd9` and the head of branch `baseapp` |
| Ledger secure SDK | `v27.1.2` |
| Speculos ELF | `compiled_app_binaries_testnet` of CI run 39610018829 (expires 2027-01-19), `nanos2/bin/app.elf`, sha256 `9203f021ea2e552122249819e8ea9554317a42224219dbfd6017c09a26e599f4` |
| Intent TLV golden vectors | generated by `build_intent_tlv` and `build_group_tlv` in `tests/vault_client.py` @ `d74bf278`, a commit in both the public `LedgerHQ/app-babylon-vault` and `LedgerHQ/app-babylon-vault-dev`, where it is an ancestor of `2733b7dd9`; those two functions, the `_ktlv` and `_tlv_*` helpers and the `TAG_*` and `VAULT_*` constants they read are source-identical at both commits (function-level diff of the file); checked by `src/__tests__/intentTlv.test.ts` |
| Vendored `ledger-bitcoin` vectors | fixtures commit and oracle pin in `src/vendor/ledger-bitcoin/README.md` |

The only firmware source change between 0.11.0 and 0.11.1 is `src/display.c` (Screen 1
unverified-caller warning; Screen 2 adds the Keepers and Challengers rows, keeps the
parameters and every vault group mandatory and makes only the key list skippable). The
approval-screen strings the Speculos suite targets are unchanged and the suite passed
against the pinned ELF; every other file step 2 lists is identical between the two
revisions, so no mirrored host literal moved.

Comments name firmware functions and constants (`_validate_display_refund`,
`SW_CAP_EXCEEDED`), never file lines or commit hashes: lines move every release and
nothing checks them. This file is provenance, not a correctness check. The behaviour
check is the Speculos suite under `src/__tests__/e2e/` against the pinned ELF; it is not
wired into CI and runs by hand with `SPECULOS_URL` set.

## Bumping the pin

1. Update the table and `PINNED_APP_VERSION` in `src/__tests__/e2e/speculos.e2e.test.ts`.
   The provider's `MIN_APP_VERSION` is a product decision released together with
   Ledger's deployment: re-evaluate it against the firmware diff, never raise it because
   the pin moved. `FIRST_UNSUPPORTED_APP_VERSION` is an exclusive ceiling: once step 2
   passes it must admit the pinned version, or the provider refuses the app this file
   vouches for.
2. Read the firmware diff between the two revisions for every rule the host mirrors:
   `src/sign_psbt_validate.c`, `src/sign_psbt_validate_helpers.c`,
   `src/sign_custom_inputs.c`, `src/vault_tlv.c`, `src/vault_constants.h`,
   `src/vault_script.c` and `src/vault_script.h`, `src/vault_intent.h`,
   `src/vault_intent_tags.h`, `src/vault_context.c` and `src/vault_context.h`,
   `src/bip322.c` and `src/bip322.h`, `src/display.c`, `src/apdu_handler.c`,
   `src/handler/approve_vault_intent.c` and `approve_vault_intent_core.h`,
   `src/handler/derive_context_hash.c`, `src/handler/derive_vault_secrets_core.h`,
   `src/handler/get_vault_state.c`, `src/globals.h`, `Makefile`, `docs/apdu.md`,
   `tests/vault_client.py`, and the test builders the host fixtures copy:
   `tests/test_sign_psbt_validate.py` and `tests/test_screen4_claim.py` through
   `tests/test_screen7_pop.py`; in the base app, `Makefile`, `src/constants.h`,
   `src/commands.h`, `src/crypto.c`, `src/common/psbt.h`, `src/boilerplate/sw.h`,
   `src/boilerplate/dispatcher.c`, `src/boilerplate/io_ext.c` and
   `src/boilerplate/io_ext.h`, `src/handler/get_extended_pubkey.c`,
   `src/handler/register_wallet.c`, `src/handler/sign_psbt.c`, `src/handler/sign_psbt/`
   and `src/handler/lib/`. If the secure SDK tag moved, read its IO-layer and status-word
   diff too.
   Re-check every mirrored literal on the host side: `src/deviceCaps.ts`,
   `src/intentTlv.ts`, `src/envelope.ts`, `src/delegatedClaimPsbt.ts`,
   `src/refundPsbt.ts`, `src/reclaimPsbt.ts`, `src/popPsbt.ts`, `src/policyPsbt.ts`,
   `src/walletPolicy.ts`, `src/rawApdu.ts`, `src/signPsbt.ts`, `src/signPsbtLoop.ts`,
   `src/signPsbtPrepare.ts`, `src/expectedSignatures.ts`, `src/derivation.ts`,
   `src/vaultCommands.ts`, `src/errors.ts`, `src/bip86Path.ts`, `src/dmkSession.ts`,
   `src/vendor/ledger-bitcoin/clientCommands.ts`, `merkelizedPsbt.ts`, `psbtv2.ts` and
   `README.md`, the fixtures under `src/__tests__/e2e/`
   and `src/__tests__/fixtures/`, the generators under `scripts/`, and the approval-screen
   strings the Speculos suite targets. Outside this package,
   re-check the device-behaviour comments in every file the first paragraph covers: the
   wallet-connector `src/core/wallets/btc/ledger-vault/`, and the ts-sdk
   `src/tbv/core/deposit-terms/`, `src/tbv/core/services/delegated-claim/` and
   `src/tbv/core/primitives/psbt/`.
3. Run the Speculos suite by hand against the new ELF. Start the container with
   `docker run --rm -d -p 5055:5055 -v <extracted dir>/nanos2/bin:/app ghcr.io/ledgerhq/speculos:latest --model nanosp --display headless --api-port 5055 --seed "<the firmware's tests/conftest.py MNEMONIC>" /app/app.elf`
   and run `SPECULOS_URL=http://127.0.0.1:5055 pnpm --filter @babylonlabs-io/ledger-vault-signer exec vitest run src/__tests__/e2e/`.
   The seed must be the firmware functional-test mnemonic: the suite's key self-check
   compares the device's `m/86'/1'/0'/0/0` key with its fixture.
4. If `build_intent_tlv`, `build_group_tlv`, the `_ktlv` and `_tlv_*` helpers or the
   `TAG_*` and `VAULT_*` constants in `tests/vault_client.py` changed, regenerate the intent TLV golden
   vectors and update that row; the rest of that file changes often and does not feed the
   vectors. If the base app moved, run the vendor README's re-diff procedure on the
   vendored `bitcoin_client_js` copies; regenerate the vendored vectors only when the
   fixtures commit or the oracle pin in that README changes.
